# 🏠 膳待家 · Umami Skill for Health

> **让团团住进你正在使用的 AI 窗口。**

膳待家 Umami 是一个基于 [Agent Skills](https://agentskills.io) 标准的对话式个人健康管家。你不用再打开一个专门的健康 App：一句“中午吃了牛肉面”，它帮你记下；一句“冰箱里有鸡蛋和西红柿”，它先看现有食材和忌口，再帮你安排下一餐；一句“今天该做什么”，它从真实记录里给出一小步行动。

本仓库是 **Skill 版**：数据操作通过零依赖 Python 脚本落到本地 SQLite，AI 助手负责理解自然语言与组织建议。它与 [膳待家 Web 版](https://github.com/renchenxuan/Umami) 的健康领域规则保持一致，但不虚构 Web 的界面、多会话和模型管理能力。

**Skill v0.2 · 对齐 Umami Web v4.0**

> 🌐 想要完整的“今日 / 快速记录 / 冰箱 / 问团团”厨房驾驶舱，请使用 [Umami Web v4.0](https://github.com/renchenxuan/Umami)。想在当前 AI 对话里顺手记录，就安装本 Skill。两者可以按场景选择。

## 为什么需要一个 Skill

健康管理最难的不是知道该吃什么，而是让记录发生在生活经过的地方。

程序员的上午可能从咖啡开始，午餐在会议间隙解决，晚上又在屏幕前忘了起身。专门打开一个 App，往往就是“等有空再说”；但当你已经在 AI 窗口里时，一句“我刚吃了两个包子”，就是最自然的记录入口。

膳待家把这件事做得更有分寸：确定性的读写交给脚本，模型不编造数据库里的事实；推荐前先看冰箱和偏好，过敏原是硬约束；营养数字写成估算；遇到症状不越界诊断。它不是一位假装全知的医生，而是一位愿意陪你把下一步做小、做实的生活管家。

## 与 Web v4.0 的关系

Web 版把同一套健康工作流做成可视化产品：

`今日状态 → 快速记录 → 下一步行动 → 最近记录 → 问团团`

Skill 版把它翻译成对话工作流：

`stats 今日概览 → 选择一个动作 → 调用对应脚本 → 返回真实回执 → 再决定下一步`

两者共享这些产品原则：

- 首次使用先认识团团、先记录一件小事，不自动发送示例消息；
- 饮食、训练、体重、习惯、食材新增等低风险记录直接完成并明确回执；
- 清空数据、修改健康偏好、归档已有记录等高风险操作先确认；
- 营养与保鲜时间是估算，用户实际记录与 AI 推测必须分开；
- 本地结构化数据操作不因首页或概览加载而隐式外发。

Skill 不包含 Web 的视觉界面、拖拽看板、浏览器导航、Web 多会话或 Web 提供商配置。对话窗口本身是 Skill 的入口。

## 功能亮点

- 🧭 **今日闭环**：`stats` 一次读取今天的饮食、训练、习惯、最新体重、临期食材、目标、购物清单、最近记录与下一步行动
- 🧊 **冰箱管理**：添加、更新、归档、按冷藏 / 冷冻查看，自动给出新鲜 / 临期 / 已过期估算
- 📸 **图片识别工作流**：助手先展示识别结果，得到确认后再批量保存食材
- 🍳 **菜谱与购物**：先看冰箱和个人偏好，优先消耗临期食材，过敏与忌口是硬约束
- 🍚 **饮食记录**：自然语言识别餐次与食物，结构化保存三餐和加餐
- 📊 **营养估算**：给出卡路里与三大营养素的估算、份量假设和不确定性
- 🏋️ **训练与身体数据**：记录训练时长、体重、体脂，结合真实趋势讨论目标
- 🎯 **目标与习惯**：追踪减脂 / 增肌等目标，记录睡眠、饮水和日常习惯
- 🧰 **可恢复数据包**：导出 JSON，预览后合并导入；导入前自动创建 SQLite 备份，默认不覆盖已有记录
- 🛡️ **健康安全边界**：不诊断、不处方、不调整药物；出现紧急警示时优先建议就医

## 隐私边界：把“本地”说准确

- `health_db.py` 只使用 Python 标准库，只读写用户指定的本地 SQLite 文件，不主动调用外部 API。
- 本地数据库不保存模型 Key、地图 Key 或系统凭据；导出包也不包含这些内容。
- Skill 运行在宿主 AI 助手的对话里。用户发给 AI 的文字、图片和上下文是否会发送给云端模型，由宿主助手的提供商、配置和隐私政策决定，不由本脚本控制。
- 处理敏感健康内容前，应使用宿主提供的 AI 授权 / 隐私确认；如果宿主没有明确机制，请先征得用户同意。

因此，“本地优先”指数据脚本的存储与读写边界，不等于宿主模型天然不会看到对话内容。

## 快速开始

需要 Python 3.10+，仅使用标准库，无需 `pip install`。

### 安装

**Windows PowerShell：**

```powershell
.\install.ps1
```

**macOS / Linux：**

```bash
./install.sh
```

安装后重启 AI 助手，使其重新发现 `umami-health` Skill。

### 第一次使用

第一次涉及健康数据时，助手会运行幂等初始化：

```bash
python "<本技能目录>/scripts/health_db.py" init
```

当返回 `first_run: true`，团团会先用三步带你认识膳待家：认识团团、记录一件小事、把生活交给膳待家整理。它只展示本地静态说明，不会自动发消息或偷偷调用模型。

### 数据位置

| 优先级 | 位置 |
|---|---|
| 1 | 命令行 `--db` 参数 |
| 2 | 环境变量 `UMAMI_HEALTH_DB` |
| 3 | 默认 `~/.umami/health.db` |

## 常用命令

以下 `<py>` 指：

```bash
python "<本技能目录>/scripts/health_db.py"
```

| 目标 | 命令 |
|---|---|
| 今日概览 | `<py> stats` |
| 冰箱 | `<py> ingredients list` / `add` / `update` / `archive` |
| 饮食 | `<py> diet log --meal 午餐 --foods '米饭,清蒸鲈鱼'` |
| 训练 | `<py> workouts log --activity 慢跑 --duration 30` |
| 身体 | `<py> body log --weight 72.5 --fat 20.1` |
| 目标 | `<py> goals set --name 减脂 --target 减到65kg` |
| 习惯 | `<py> habits log --habit 睡眠 --value 睡了7小时` |
| 购物 | `<py> shopping add --name 西兰花` / `check <id>` |
| 资料 | `<py> prefs get` / `set` |
| 菜谱 | `<py> recipes save` / `list` / `show <id>` |
| 食材大全 | `<py> foods search 番茄` / `categories` |
| 导出 | `<py> export --output umami-health.json` |
| 导入预览 | `<py> import-preview --file umami-health.json` |
| 确认导入 | `<py> import --file umami-health.json --yes` |

`stats` 返回的 `metrics.diet_kcal` 和 `calorie_target` 在当前 Skill 数据模型中为 `null`，因为 Skill 不会为了填满卡片而编造热量；只有明确保存了营养估算时，助手才应按估算规则报告。

## 写入规则

**可以直接完成的低风险记录：**

饮食、训练、体重 / 体脂、习惯、添加或更新食材、加入购物清单、保存菜谱、更新目标状态。命令成功后必须明确告诉用户“已记录”或“已保存”。

**必须先确认的操作：**

清空冰箱、清空购物清单、修改人数 / 口味 / 过敏原 / 身高 / 年龄等健康偏好，以及归档已有记录。确认前不执行，也不声称已经生效。

Skill 当前提供的是脚本成功回执和安全归档，不包含 Web 版那种每条 Agent Action 的前端撤销按钮；不要把归档或数据库备份描述成即时撤销。

## 可恢复健康数据包

```bash
<py> export --output umami-health.json
<py> import-preview --file umami-health.json
<py> import --file umami-health.json --yes
```

导出包包含 Skill 管理的偏好、冰箱食材、饮食、训练、身体数据、目标、习惯、菜谱和购物清单。导入会先整体校验，预览不写数据库；确认导入前自动创建备份，默认合并而不是覆盖。空数据库尽量保留原 ID；发生冲突时为导入记录分配新的本地 ID。Skill 没有 Web 的消息、提醒、日程和看板表，因此这些内容不会被伪装成可恢复数据。

## 设计翻译

| Web v4.0 产品能力 | Skill 版落点 |
|---|---|
| 今日页 | `stats` 的今日指标、下一步行动、最近记录 |
| 快速记录 | 饮食 / 训练 / 身体 / 习惯脚本 |
| 问团团 | 宿主 AI 对话 + `SKILL.md` 的输出规则 |
| 首次引导 | `init` 返回 `first_run`，对话中展示三步静态说明 |
| AI 授权 | Web 由应用提供全局授权；Skill 由宿主助手的模型与隐私机制负责，脚本不伪造授权闸门 |
| 自动记录回执 | 脚本成功 JSON + 助手明确回复；Skill 当前不伪造 Web Action 撤销能力 |
| 可恢复导出 | `export` / `import-preview` / `import`，只覆盖 Skill 自己的本地数据 |

核心架构仍然是：确定性的操作一律走脚本，模型只负责理解、判断和表达；领域知识按需从 `references/` 加载。
