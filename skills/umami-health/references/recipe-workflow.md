# 菜谱 / 购物清单工作流

当用户想要菜谱、三餐安排、一周饮食计划、购物清单或"冰箱能做什么菜"时，严格按以下流程执行。

## 流程

1. **先读冰箱**：运行 `ingredients list`，绝不凭空假设冰箱里有什么，也不跳过这步直接编菜谱。输出中标注🟡临期/🔴已过期食材。
2. **再读偏好**：运行 `prefs get`，读取人数、口味、忌口、菜系、计划天数等，做到个性化。
3. **优先消耗**：优先使用冰箱里已有的、临期或易坏的食材，减少浪费。
4. **硬约束**：用户的过敏与忌口绝对不能出现在菜谱中；份量按人数计算。
5. **保存历史**：菜谱生成并经用户认可后，运行 `recipes save --title … --ingredients '[…]' --steps '[…]'` 保存，方便以后查询。

## 输出格式

- 用「📅 第 N 天 / 早·午·晚」的结构分餐呈现。
- 每道菜标注主要食材与大致份量。
- 购物清单：对比冰箱现有食材，列出还缺的（名称 + 数量 + 分类），并在回复中先展示；经用户同意后再逐项 `shopping add` 落库。

## 冰箱拍照识别

用户发来冰箱/食材照片时：

1. 用视觉能力识别图中所有食材：名称、预估数量、分类（参考 `foods categories` 的 11 个分类）。
2. 在回复中清晰列出识别结果，让用户确认或修正。
3. 经确认后逐项保存：`ingredients add --name <名称> --quantity <数量> --source agent`（分类与存放分区会自动推断；肉类/水产默认冷冻，其余冷藏）。
4. 只识别食材，忽略非食物；无法判断数量写"若干"。

## 示例对话片段

> 用户：冰箱里有鸡蛋和西红柿，给 2 个人做一顿晚餐
>
> 助手：先运行 `ingredients list` 确认食材与保鲜状态、`prefs get` 确认忌口 → 输出 2 人份晚餐菜谱（如番茄炒蛋 + 米饭，标注份量）→ 询问是否保存菜谱与补充购物清单。
