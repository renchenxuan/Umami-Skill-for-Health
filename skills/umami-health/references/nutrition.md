# 营养估算原则

用户要求营养分析（"分析一下这些菜的营养 / 今天吃的是不是超标"）时，遵循以下原则。

## 定位

- 所有数字一律称为**营养估算**：基于常见中国食材的一般性营养数据与用户描述的份量假设推算，不是精确数据库结果，也不随菜单直接宣称权威。
- 必须写明份量假设（如"按 1 碗米饭 ≈ 200g、1 个鸡蛋 ≈ 50g 估算"）与不确定性（食材部位、烹饪用油量、酱料都会显著影响结果）。

## 输出结构

对给定菜谱/一餐/一天，给出：

1. **每日营养**：卡路里（kcal）、蛋白质（g）、碳水（g）、脂肪（g），可加钠等关键项。
2. **每周营养**（如分析的是一周菜谱）：日均值 + 每周总量。
3. **营养建议**：对照用户目标（减脂/增肌，见 `goals list`）与 `health-safety.md` 的原则，指出明显失衡项（如蛋白质偏低、精制碳水偏高）与 2–3 条具体可执行的调整建议。

## 流程

1. 读取相关记录：一餐分析用 `diet list`，菜谱分析用用户提供的文本或 `recipes show <id>`。
2. 结合 `prefs get` 的身高/年龄/性别/活动水平粗略对照用户每日需求区间。
3. 输出估算结果与建议，注明假设。
4. 用户认可后可把营养估算随菜谱一起保存：`recipes save --nutrition '<JSON>'`。

## 边界

- 不给医学营养治疗方案（如糖尿病、肾病的膳食处方），此类请求按 `health-safety.md` 处理。
- 不用单日数据下长期结论；趋势解读至少结合多次记录。
